# SoftwareProducts: что исправлено по заданию (Вариант 21)

## Как открыть и запустить в IntelliJ IDEA

1. File → Open → выбрать папку `SoftwareProducts` (корень с `build.gradle`). IDEA подхватит Gradle-проект.
2. Project SDK: JDK 17 или новее (проверено на 21).
3. Задать переменные окружения в Run Configuration для `SoftwareProducts`:
   - `DB_URL` например `jdbc:mysql://localhost:3306/software_products`
   - `DB_USER`, `DB_PASSWORD`
4. Запустить класс `kurban.softwareProducts.SoftwareProducts`.

Важно: в таблице `releases` поле бывшее `created_at` переименовано в `release_date`. Если база уже создана старой версией, удалите таблицы (или старую колонку `created_at`) перед запуском, иначе вставка упадёт из-за NOT NULL. `ddl-auto: update` сам колонку не удалит.

## Соответствие ТЗ

### Пять операций для каждой сущности
| Операция | Пример | Ответ |
|---|---|---|
| Чтение списка | `GET /api/releases` | 200, массив |
| Чтение по id | `GET /api/releases/{id}` | 200, объект; 404, если нет |
| Создание | `POST /api/releases` | 201, объект с `id` |
| Обновление | `PATCH /api/releases/{id}` | 200, объект; 404, если нет |
| Удаление | `DELETE /api/releases/{id}` | 204; 404, если нет |

Было: не было `GET /{id}`, использовался `PUT`, а не `PATCH`.

### Сущности и поля
- **software-products**: `name`, `responsibleUserId` (User), `currentReleaseId` (версия этого же продукта).
- **development-tasks**: `productId`, `assigneeUserId` (User), `releaseId` (версия этого продукта), `progress` (`BACKLOG`, `TO_DO`, `IN_PROGRESS`, `DONE`; по умолчанию `BACKLOG`).
- **releases**: `productId`, `number`, `status` (`ACTUAL`, `DEPRECATED`), `releaseDate` (дата выпуска).
- **release-checks**: `releaseId`, `name`, `type` (`REQUIRED`, `OPTIONAL`), `result`.
- **users**: `username`.

### Серверное время
`releaseDate` ставится сервером (`LocalDate.now()`) при создании и не принимается из запроса. Было: поле `createdAt` приходило из тела.

### Удаление без битых ссылок
- **Удаление продукта** каскадно удаляет его версии, проверки версий и задачи.
- **Удаление версии** удаляет её проверки и очищает `currentReleaseId` у продукта. Если на версию ссылаются задачи, удаление отклоняется с 409, сначала задачи нужно переназначить. Выбрано так, чтобы не потерять работу молча.
- **Удаление пользователя** отклоняется с 409, если он ответственный за продукт или исполнитель задачи.

Ссылки при создании и обновлении проверяются: продукт, пользователь и версия должны существовать, версия должна принадлежать нужному продукту. Иначе 400.

### Архитектура
- **Контроллеры** принимают запрос, маппят в сущность и обратно в ответ (record-ы `…Request` и `…Response` внутри контроллера). Сущности JPA наружу не отдаются.
- **Сервисы** содержат проверки, PATCH-логику, каскады и бизнес-правила.
- **Репозитории** работают с БД и содержат только выборки, нужные для проверок и каскадов.

### Ошибки
Единый обработчик `GlobalExceptionHandler`:
- 404: сущность не найдена
- 409: нарушение ссылочной целостности при удалении
- 400: неверные или отсутствующие данные, либо несуществующая ссылка

Было: ошибки давали 500.

### Прочее
- `UserController`: метод `createRelease` переименован в `createUser`.
- `main` сделан `public`, иначе запуск из IDEA может не найти точку входа.
- MapStruct убран из `build.gradle`, он не использовался. Маппинг сделан вручную в контроллерах.
